# GitHub-Style Callouts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add nested GitHub-style and fenced-Div callouts with context-aware quote editing, empty-container navigation, semantic export lowering, and complete documentation.

**Architecture:** A pure callout grammar reads both source forms into one model. The block splitter keeps ordinary quote stacks and callout-bearing fenced Divs as single blocks; parser repair turns the source into callout nodes while preserving offsets. The editor renders a callout panel outside the caret and exact source inside it, while a shared quote-edit module owns Enter and nested-level exit rules for quotes and callouts.

**Tech Stack:** TypeScript, unified/remark/mdast, remark-directive, Tauri, Pandoc, Node checks, Tauri MCP probes.

**Spec:** `docs/superpowers/specs/2026-10-28-callouts-design.md`

## Global Constraints

- The raw Markdown text is the only source of truth; every edit is a raw-text range replacement.
- Syntax modules never import the DOM.
- GitHub marker syntax recognizes only `NOTE`, `TIP`, `IMPORTANT`, `WARNING` and `CAUTION`, case-insensitively.
- A marker with an unknown label, suffix text, escaped brackets or malformed quote prefix remains an ordinary blockquote.
- Fenced-Div syntax accepts `.callout` plus one `.callout-<kind>` class, or a lone `.callout-<kind>` shorthand.
- Built-in titles are fixed English Markdown vocabulary: `Note`, `Tip`, `Important`, `Warning`, `Caution`.
- A custom kind without `title=` humanizes its class suffix without consulting the UI locale.
- Fenced-Div IDs and attributes are preserved for Pandoc and filters but create no Yi reference target.
- Pandoc's `alerts` extension remains disabled.
- GitHub and fenced-Div callouts lower to the same semantic `.callout` `Div` on export.
- Ordinary quote blocks and GitHub-style callouts use the same context-aware Enter rules.
- Double Enter removes exactly one inner quote level, never every level at once.
- Enter after a completed child block inserts one prefixed empty line, not the two-line paragraph break.
- Empty quote and fenced-Div callouts keep a navigable body anchor reachable from either side.
- Navigation across an empty callout never edits the document.
- A callout is a block-level source-mode surface, not an inline `RevealableNodeComponent`.
- Use the Tauri MCP probe harness for editor behaviour and Node checks for pure rules.
- Do not merge the branch into `main` without an explicit request.

- [ ] **Step 3: Implement the grammar**

`readCallout` must:

- split source into lines without changing offsets;
- recognize an alert marker only on the first content line of its innermost
  quote level;
- accept zero to three leading spaces before the first `>`;
- accept one or more `>` levels, each followed by at most one space;
- accept only the five built-in labels, case-insensitively;
- reject suffix text, escaped markers and unknown labels;
- consume only contiguous quote lines with the same outer prefix chain;
- locate an optional quoted separator after the marker and exclude it from the
  body;
- parse a closing `:::` line with a fence at least as long as the opening
  fence;
- parse fenced-Div attributes with `attributeBlockAtEnd`;
- accept the same outer quote-prefix chain before a fenced-Div opening and
  closing line;
- recognize `.callout` plus `.callout-<kind>` or the lone shorthand class;
- preserve the ID, classes and attributes;
- derive a fixed built-in title or an explicit/humanized custom title.

`calloutsForParsers` must replace only the post-fence attribute spelling of a
callout fenced Div with `callout-<kind>` padded by spaces to the same line
length. It must not transform source inside code fences, math or frontmatter.

- [ ] **Step 3: Implement the pure edit rules**

`enterInQuote` must derive from the source at `offset`, not key history:

- a paragraph context inserts two active-prefix empty lines;
- when the caret is already on the second empty paragraph, it removes one `>`
  from every empty line in the pair;
- `completed-child` inserts one active-prefix empty line;
- list, table, code and equation contexts return `null`, which tells the
  editor to run that construct's existing edit and prefix its inserted lines;
- prefix generation is `' >'.repeat(depth)` normalized to one space between
  levels.

`materializeCalloutBody` handles the empty-anchor case without changing the
document during navigation. It adds the required newline and quote prefix, or
the newline before a Div closing fence, only when the first character is typed.
