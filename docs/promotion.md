# Yi promotion copy

Use this page as the source for repository metadata, release announcements and community posts.

## Positioning

Primary audience: researchers, academics and long-form writers already using Markdown, LaTeX,
Pandoc or Zotero.

English pitch:

> Yi is a local-first WYSIWYG Markdown editor for notes, research and long-form writing. Keep
> ordinary files, link ideas, manage citations, write mathematics, and export through reusable
> Pandoc templates.

Chinese pitch:

> Yi 是一款本地优先的所见即所得 Markdown 编辑器，面向笔记、研究资料与长文写作。文件始终是普通
> Markdown，同时内置链接、交叉引用、文献引用、数学公式与 Pandoc 模板导出。

Three differentiating advantages:

- WYSIWYG editing without giving up raw Markdown.
- Researcher-oriented citations, cross-references, equations and theorem blocks.
- Reusable Word, LaTeX, EPUB, HTML and PDF template packages.

## Show HN draft

Title:

```text
Show HN: Yi – local-first WYSIWYG Markdown for research writing
```

Body:

> I built Yi after finding that plain-text notes and publication-quality output often live in
> separate tools. Yi keeps a normal folder of Markdown files, renders links, tables, formulas,
> callouts and theorem-like blocks in place, and lets the caret reveal Markdown only where it is
> being edited. It supports CSL or BibTeX citations and reusable Pandoc templates for Word,
> LaTeX, HTML, EPUB and PDF.
>
> The desktop app is Tauri, Rust and TypeScript. The website contains real screenshots, template
> examples and the full guide. I would especially value feedback from people who write papers,
> maintain a Zettelkasten, or publish Markdown with Pandoc.

Use this when posting to Tauri, Rust, TypeScript, Markdown or open-source communities:

> Yi is a Tauri + Rust + TypeScript desktop Markdown editor. The repository includes architecture
> guides, a fast Node rule suite and a real-app MCP probe harness. Contributions are especially

> export compatibility.
>
> Start here: https://github.com/yungleung/yi/blob/main/CONTRIBUTING.md
>
> Good first issues: https://github.com/yungleung/yi/labels/good%20first%20issue

## Launch checklist

- Publish signed platform builds through GitHub Releases.
- Include a 30–60 second demo covering editing, links, citations, mathematics and export.
- Set the repository homepage and social preview.
- Add `good first issue` and `help wanted` labels.
- Seed several concrete, self-contained issues before asking for contributors.
- Launch in one research-writing community first, respond to feedback, then broaden.
- Measure release downloads, issue quality and returning contributors rather than stars alone.
